# Socket investigation: @cloudflare/kumo 2.6.0

Reviewed October 7, 2026. Scope: published Kumo tarball, registry metadata/signature, npm attestation contents, version-tagged upstream source/build workflow, embedded source maps, and static behavior indicators. This investigation made no source changes or Socket policy changes.

**Disposition: retain the exact lockfile version for the compatible EmDash stack, document this investigation, and require the fresh PR's Socket results to be reviewed. Do not add an ignore comment, blanket suppression, or claim that the package is malware-free.** The evidence supports ordinary production minification and bundled syntax-highlighting WebAssembly as a plausible explanation; it does not establish which file triggered Socket's classifier.

## Alert and necessity

[Socket's PR #3 comment](https://github.com/nexusct/nexus-emdash/pull/3#issuecomment-5389105939) reports “Obfuscated code,” High severity, 0.90 confidence, for Kumo 2.6.0. The recorded path reaches Kumo through EmDash 0.34.0; Kumo is the CMS/admin component library. The published alert is a heuristic warning, not a malware verdict. [Socket's own documentation](https://socket.dev/alerts/obfuscatedFile) says its JavaScript algorithm detects minification as well as obfuscation.

Metadata claims were checked against the source repository rather than accepted alone.
- The downloaded [npm tarball](https://registry.npmjs.org/@cloudflare/kumo/-/kumo-2.6.0.tgz) matches the registry's SHA-512 integrity exactly. SHA-256: `37812fb253d17390b70975501253da08a734954ec8480657d9863581cdbaba6b`. Integrity: `sha512-rcUUvhrtxI0veNJZLgKVSnxH/L0M48jtc4UoNhvu0l0RiRmjHORFTBYq/phFQyt7JGG3s98QPZc5w1eW+UQIOg==`.

This authenticates the registry signature for those bytes; it does not independently prove upstream build reproducibility.
- The decoded [npm SLSA provenance](https://registry.npmjs.org/-/npm/v1/attestations/@cloudflare%2fkumo@2.6.0) has a matching tarball subject digest and identifies commit `ff935c4736023dcc31e9505b4bbb1f8fadc3eb73`, Cloudflare's `.github/workflows/release.yml`, and [Actions run 27975059478](https://github.com/cloudflare/kumo/actions/runs/27975059478/attempts/1). ## Source and behavior evidence

1. [Versioned Vite configuration](https://github.com/cloudflare/kumo/blob/ff935c4736023dcc31e9505b4bbb1f8fadc3eb73/packages/kumo/vite.config.ts) explicitly enables esbuild production minification, sourcemaps, bundled vendor chunks and code splitting. The tarball includes 178 JavaScript files and 170 `.js.map` files.
2. All **76 located unique internal sources** embedded in the maps match their upstream commit files exactly. One additional map source, `ai/schemas.ts`, is generated during the registry build and is not committed; the upstream [generator](https://github.com/cloudflare/kumo/blob/ff935c4736023dcc31e9505b4bbb1f8fadc3eb73/packages/kumo/scripts/component-registry/index.ts) writes it. Maps are supporting evidence, not proof that compiled output is identical to a reproducible build.
3. The 622,434-byte `dist/chunks/wasm-oj22f8usru9h7dzg.js` contains bundled Shiki/Oniguruma WebAssembly for syntax highlighting. Its map's `sourcesContent` exactly matches the published `@shikijs/engine-oniguruma@4.0.0` `dist/wasm-inlined.mjs` (source SHA-256 `39a43f044abd46544a20151fe88c4c898df1a0bf496ca111b56460b16e730be2`). [Kumo's source](https://github.com/cloudflare/kumo/blob/ff935c4736023dcc31e9505b4bbb1f8fadc3eb73/packages/kumo/src/code/provider.tsx) expressly selects `shiki/wasm` for its WASM highlighting engine. The compiled chunk SHA-256 is `c18ac965cf996d77012a94aee847412fb069cf218e477dcf0fb580e25824a0e3`; its map SHA-256 is `74ca50188377a713793e9b4dbc50ef4e3c3dd4b5b71542a3ea9d745908e7a7e3`.
4. The published package has no `preinstall`, `install`, `postinstall` or `prepare` script. Static scans of the 178 JavaScript files found no direct `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `eval(...)`, `new Function(...)` calls, or `.ssh`/`.aws`/`.npmrc` path patterns. Referenced environment keys were only `NODE_ENV` and `VSCODE_TEXTMATE_DEBUG`. These are pattern-based checks, not exhaustive execution analysis.
5. The only child-process indicator is the readable `bin/kumo.js` CLI launcher, byte-identical to [upstream](https://github.com/cloudflare/kumo/blob/ff935c4736023dcc31e9505b4bbb1f8fadc3eb73/packages/kumo/bin/kumo.js). It imports the built local CLI; in an unbuilt source checkout it can invoke the local Node process with `tsx`. Explicit CLI commands read component documentation or write requested local configuration/component files. CLI file writes are not install-time behavior.

## Limits and release handling

The Socket package overview returned HTTP 403, and the organization-specific alert redirected to login. The exact flagged file and detector evidence were therefore unavailable; do not label this a confirmed false positive. No full upstream rebuild, instrumented runtime/network analysis, WASM disassembly or exhaustive transitive-dependency review was performed. Registry provenance and source-map correspondence reduce uncertainty but cannot prove absence of malicious behavior.

Retain dependency locking and fresh Socket monitoring. A new unexplained payload, signature/provenance verification failure, unexpected lifecycle hook, or fresh Socket malware/network alert requires renewed review before release. The investigated warning alone does not establish a blocker after the documented review; organizational acceptance and the fresh scan remain visible release-review decisions. Cloudflare runtime/deployment validation is outside this supply-chain inspection.
